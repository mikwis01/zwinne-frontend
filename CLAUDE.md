# Frontend

React SPA: Vite, TanStack Router (file-based), TanStack Query + axios, Tailwind 4.

## Commands

- `npm run dev`, `npm run build`, `npm run typecheck`, `npm run lint`, `npm run format`
- Lint is oxlint (not ESLint), config in `.oxlintrc.json`. TypeScript is v7.
- `src/routeTree.gen.ts` is generated by the router Vite plugin on dev/build. Never edit it, but commit it.

## Structure

- `src/routes/` — file-based routes. A route file holds the `Route` definition and the page component.
- Page-specific components and hooks live next to the route in a `-`-prefixed folder (ignored by the router), e.g. `routes/users/-components/UsersTable/`, `routes/users/-hooks/use-users-filters.ts`.
- `src/components/` — components shared by multiple pages. One component per folder: `ComponentName/ComponentName.tsx` + `index.ts` barrel export.
- `src/hooks/` — only hooks shared across multiple pages.
- `src/api/` — `queryOptions` and mutation functions, one file per resource (e.g. `api/users.ts`).
- `src/lib/` — configured clients (`apiClient`, `queryClient`) and `cn()`.
- `src/utils/` — pure helper functions.
- Import from `src` via the `@/` alias, not long relative paths.

## Naming

- Components: PascalCase, filename matches folder name.
- Everything else (hooks, api, utils): kebab-case filenames, camelCase exports.
- Types: always `type`, never `interface` (except for declaration merging, e.g. `Register`, `ImportMetaEnv`).
- Components and functions are arrow functions (`func-style` is enforced).
- `use` prefix (and `use-` filename) only for real hooks, i.e. functions that call other hooks. Plain functions that build configs or compute values are `getX`, not `useX`.

## Data fetching

- Never call `apiClient` directly in components and never fetch in `useEffect`. Go through React Query.
- Define queries with `queryOptions` in `src/api/`, so the key and the fetcher live in one place:

```typescript
export const userQueryOptions = (id: string) =>
  queryOptions({
    queryKey: ['users', id],
    queryFn: () => apiClient.get<User>(`/users/${id}`).then(res => res.data)
  })
```

- For data a page needs to render, preload it in the route `loader` with `context.queryClient.ensureQueryData(...)` and read it with `useSuspenseQuery(...)` in the component. That way the component has no loading or error branches.

## Mutations — never try/catch

Use `onSuccess` / `onError` on `useMutation` and its `isPending` flag, not manual `try/catch` or `isLoading` state.

To refresh data after a mutation, invalidate the affected queries in `onSuccess` with `queryClient.invalidateQueries({ queryKey })`. Don't call `refetch()` or manually update local state.

```typescript
const queryClient = useQueryClient()
const { mutate, isPending } = useMutation({
  mutationFn: updateUser,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['users'] }),
  onError: () => {
    // show error toast
  }
})
```

## State

- Server data lives in React Query. Don't copy it into `useState` or context.
- Context is for data that's already fetched or passed from a parent, not a default state layer. Prefer props or calling the query hook directly over introducing a new context.
- URL state (filters, pagination, tabs) goes in route search params (`validateSearch`), not `useState`.

## Errors

Errors thrown in route components and loaders are caught by the router's error boundary (`defaultErrorComponent: ErrorFallback` in `src/router.ts`). Don't hand-roll error states for page data. Use a route-level `errorComponent` only when a page needs a custom one.

## Styling

- Tailwind only, no inline `style` and no CSS files besides `src/index.css`.
- Use `cn()` for conditional or merged classes (e.g. a `className` prop).
- Class order is handled by Prettier, so don't sort classes by hand.

## Git

- Branch: `FT-<ticket>-<feature-name>`, no `feature/`/`fix/` prefix.
- Commit (enforced by commitlint): `[FT-<ticket>][<type>] - <description>`, under 100 chars. Types: `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `revert`, `style`, `test`.
